React Native Upgrader v1 Coding Plan

Goal: Build a CLI that detects environment, checks compatibility, and generates a safe upgrade plan.

Step 1 - Project scaffolding
- Initialize Node.js + TypeScript project structure.
- Set up CLI entry with Commander.js.
- Add Chalk and Execa dependencies.
- Add scripts: build, dev, lint, typecheck.
- Create basic bin entry (npx runnable).

Step 2 - Core config and data
- Define ruleset schema for RN version requirements (kotlin, gradle, AGP, hermes).
- Add initial ruleset data (local JSON file).
- Create typed loader for ruleset.

Step 3 - Environment detection
- Read package.json and extract react-native version.
- Read node_modules/react-native/package.json if available.
- Parse android/build.gradle for kotlin version and AGP version.
- Parse gradle-wrapper.properties for Gradle version.
- Parse ios/Podfile for Hermes setting if present.
- Normalize detected versions and emit a single report object.

Step 4 - Compatibility checks
- Compare detected versions against target RN version rules.
- Add a library compatibility map (reanimated, navigation, firebase, gesture-handler).
- Scan installed dependencies and flag known incompatible versions.
- Produce a structured compatibility report.

Step 5 - Upgrade plan generator
- Convert reports into ordered upgrade steps.
- Generate human-readable output with clear, safe steps.
- Ensure plan is deterministic and explains why each step is needed.

Step 6 - CLI flow
- Implement command: npx react-native-upgrader --to X.Y.Z
- Wire steps: detect -> compare -> compatibility -> plan.
- Add pretty terminal output with sections and warnings.
- Exit codes: 0 for success, 1 for fatal errors.

Step 7 - Testing and samples
- Add fixtures for sample RN projects (android + ios).
- Unit tests for parsers and version comparison.
- Snapshot tests for CLI output.

Step 8 - Documentation
- Write README with usage, examples, and limitations.
- Document ruleset format and how to extend it.

Step 9 - MVP hardening
- Add error handling for missing files.
- Ensure cross-platform path handling.
- Validate target version input and provide friendly errors.
